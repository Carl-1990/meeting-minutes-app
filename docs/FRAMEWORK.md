# 会议纪要 App 开发框架（Agent 可读规格）

> 版本：v0.3（已确认：macOS、Apple M5 芯片、无 Apple 开发者账号；其余 [待确认] 条目待 Boss 确认）
> 目标读者：负责实现本项目的开发 agent / 工程师。请严格按本文件实现；标注 [默认] 的为未确认前采用的默认决策。

---

## 0. 一句话目标
一款桌面端会议记录软件：用电脑麦克风录音 → 实时转写为中文逐字稿 → 每句话带「发言人」标签（可自动识别说话人，也可手动指定）→ 结束会议后自动导出 Word 文件到桌面。最终交付一个双击即可安装的安装包。

## 1. 关键技术决策

| 项目 | 决策 | 理由 |
|---|---|---|
| 目标系统 | macOS 12 Monterey 及以上，**仅构建 Apple 芯片 arm64 版**（Boss 的电脑为 M5）[已确认] | 安装包为 `.dmg` |
| 开发语言 | Python 3.11 | 语音生态最成熟 |
| GUI 框架 | PySide6 (Qt 6) | 原生外观、支持双击编辑、易打包 |
| 录音 | `sounddevice`（PortAudio），16 kHz / 单声道 / int16 | 跨平台、低延迟 |
| 实时语音识别 | `sherpa-onnx` 流式模型：`streaming-paraformer-bilingual-zh-en` [默认] | **完全离线**、免费、实时、中英混说可用、CPU 即可跑 |
| 语音活动检测 | `sherpa-onnx` 内置 Silero VAD | 切分句子，供说话人识别使用 |
| 说话人识别 | `sherpa-onnx` 说话人嵌入模型（3D-Speaker ERes2Net 中文）+ 在线余弦聚类 | 离线、无需提前注册声纹 |
| 标点恢复 | `sherpa-onnx` 离线标点模型（ct-transformer zh-en） | 逐字稿可读性 |
| Word 导出 | `python-docx` | 生成 .docx |
| 打包 | PyInstaller 生成 `会议纪要.app`（windowed 模式）+ `create-dmg` 生成 `会议纪要.dmg` | 双击打开 dmg，把图标拖进“应用程序”即完成安装 |

> 备选（若 Boss 选择云端识别）：讯飞 / 阿里云 / 腾讯云实时语音转写 API，准确率和说话人分离更强，但需联网和按时长付费。架构中通过 `ASREngine` 接口隔离，切换只需新增一个实现类。

## 2. 功能需求（对应 Boss 原始需求编号）

### R1 录音与实时转写
- 使用系统默认输入设备（麦克风）采集音频。
- 音频以 100 ms 为一块送入流式识别器，**部分结果（partial）实时刷新**到右侧当前气泡，句子结束（endpoint / VAD 判定静音）后定稿（final）。
- 识别延迟目标：说话到文字出现 ≤ 1 秒。

### R2 必须具备的按钮
`开始会议`、`暂停会议`、`结束会议`、`发言人1` … `发言人10`（共 13 个）。

### R3 界面布局
- 左侧：功能栏（宽约 220 px，固定），从上到下：开始 / 暂停 / 结束 → 分隔线 → 发言人1~10。
- 右侧：实时对话区（可滚动），类聊天气泡，每条形如：
  `[00:03:15] 张三：今天我们讨论一下第三季度的预算……`
- 新消息自动滚动到底部；用户向上滚动查看时暂停自动滚动，回到底部后恢复。

### R4 开始会议 & 麦克风状态指示
- 点击「开始会议」→ 打开麦克风流并开始录音转写。
- 成功打开且 1 秒内检测到有效音频帧 → 按钮变**绿色**（`#2E7D32`），文字变为「会议进行中」。
- 打开失败（无设备 / 被占用 / 无权限）→ 按钮保持**灰色**并在状态栏提示「未检测到麦克风，请检查连接或系统隐私设置」。
- macOS 麦克风权限：首次点击开始时系统会弹出授权框（App 的 `Info.plist` 必须包含 `NSMicrophoneUsageDescription`，文案：「会议纪要需要使用麦克风录制会议并转为文字」）。若用户拒绝过，弹窗提供「打开系统设置」按钮，跳转 `x-apple.systempreferences:com.apple.preference.security?Privacy_Microphone`。
- 注意：macOS 拒绝授权时音频流可能“成功打开但全是静音”，因此判定绿色必须基于**实际收到非零音频帧**，不能只看流是否打开。
- 额外：按钮旁显示一个小音量条（实时 RMS），方便确认确实在收音。

### R4b 暂停会议
- 点击「暂停会议」→ 停止送音频给识别器（流保持打开），按钮文字切换为「继续会议」，开始按钮变**黄色**。
- 再次点击 → 恢复，开始按钮恢复绿色。暂停时段不计入录音文件。

### R5 发言人按钮改名
- **双击**发言人按钮 → 弹出输入框（或原地编辑），输入姓名后回车确认。
- 改名后：按钮显示新名字；**右侧已有的该发言人所有历史记录同步替换为新名字**；导出 Word 时使用新名字。
- 名称持久化到本次会议的会话数据中；可选：提供「保存为常用参会人」[建议]。

### R6 逐字稿带发言人前缀
- 每条定稿文字前加发言人名称：`发言人3：……` 或改名后 `李四：……`。
- 单击发言人按钮 = **手动指定当前说话人**（按钮高亮），之后的句子归属该发言人，直到再次切换。

### R7 结束会议 & 导出 Word
- 点击「结束会议」→ 弹出确认框（防误触）→ 停止录音 → 生成 Word：
  - 默认路径：当前用户桌面 `~/Desktop`（用 `Path.home() / "Desktop"`；若开启了 iCloud“桌面与文稿”同步，该路径依然有效）。
  - 文件名：`会议纪要_YYYYMMDD_HHMM.docx`，重名时追加 `_2`、`_3`。
  - 文档结构：标题「会议逐字稿」→ 会议信息（日期、开始/结束时间、时长、参会发言人列表）→ 正文（每条：时间戳 + 发言人加粗 + 内容）。
- 导出完成后弹窗「已保存到桌面：xxx.docx」，提供「打开文件」「打开所在文件夹」按钮。

### R8 安装包
- 交付 `会议纪要.dmg`：双击打开 → 把「会议纪要」图标拖进「应用程序」文件夹即安装完成，可从启动台打开；包含所有模型文件，**安装后无需联网、无需装 Python**。
- 只构建 arm64 版：`会议纪要.dmg`（适用 M1~M5 全系 Apple 芯片）[已确认]。
- 签名说明：
  - 无 Apple 开发者账号时：做 ad-hoc 签名（`codesign --force --deep -s -`）。首次打开需在「应用程序」里**右键 → 打开 → 打开**一次（或在 系统设置 > 隐私与安全性 里点“仍要打开”），之后正常双击使用。
  - [已确认] Boss 没有开发者账号 → 采用 ad-hoc 签名，不做公证。dmg 内附一张「首次打开说明」图片/README。
  - 若 dmg 下载后提示“已损坏，无法打开”（隔离属性导致），在说明中提供备用命令：`xattr -cr /Applications/会议纪要.app`。
  - 必须开启 Hardened Runtime，并在 entitlements 中加入 `com.apple.security.device.audio-input`，否则签名后的 App 无法使用麦克风。
- 预计安装包体积 300~500 MB（主要是语音模型）。

### R9 自动识别发言人（说话人分离）
- 模式开关（左侧顶部）：`自动识别发言人` / `手动选择发言人`，[默认] 自动。
- 自动模式算法：
  1. VAD 切出一句话（≥ 1.0 s 才做声纹，过短沿用上一位发言人）。
  2. 计算该句声纹向量（embedding）。
  3. 与已有发言人中心向量比较余弦相似度；最大值 ≥ 阈值（默认 0.55，可在设置中调）→ 归为该发言人并更新中心；否则新建下一个编号发言人（最多 10 个，满了归为最相似者）。
  4. 对应发言人按钮短暂闪烁高亮，提示“正在说话”。
- 人工纠正：
  - 右键某条记录 → 「改为发言人X」，**该条声纹自动并入发言人X**，以后识别更准。
  - 自动模式下单击发言人按钮 = 强制下一句归属该人（一次性覆盖）。
- 已知局限（需写入使用说明）：单个笔记本麦克风、多人同时说话、声音相近的人时准确率会下降；建议会议室用全向会议麦克风。

### 3.1 线程模型
- **UI 线程**：只做界面。
- **音频回调线程**（sounddevice）：只把音频块放进 `queue.Queue`，不做计算。
- **处理线程**（`QThread`，pipeline）：取音频 → 流式 ASR（partial/final）→ VAD 句段 → 声纹聚类 → 标点 → 通过 Qt 信号发给 UI：
  - `partial_text(str)`、`final_segment(Segment)`、`speaker_active(int)`、`audio_level(float)`、`error(str)`。

### 3.2 会议状态机
```
IDLE --开始--> RECORDING --暂停--> PAUSED --继续--> RECORDING
RECORDING/PAUSED --结束(确认)--> EXPORTING --> IDLE
```
按钮可用性：IDLE 时仅「开始」可点；RECORDING 时「暂停」「结束」可点；PAUSED 时「继续」「结束」可点。

### 3.3 数据模型
```python
@dataclass
class Speaker:
    id: int                 # 1..10
    name: str               # 默认 "发言人{id}"，可改名
    centroid: np.ndarray | None
    count: int

@dataclass
class Segment:
    idx: int
    start: float            # 秒，相对会议开始（不含暂停时长）
    end: float
    speaker_id: int
    text: str
    source: Literal["auto", "manual", "corrected"]

@dataclass
class MeetingSession:
    started_at: datetime
    ended_at: datetime | None
    speakers: dict[int, Speaker]
    segments: list[Segment]
    paused_total: float
```
显示和导出时发言人名称一律通过 `speakers[speaker_id].name` 实时取，因此改名会自动作用于所有历史记录。

### 3.4 ASR 接口（便于以后换云端）
```python
class ASREngine(Protocol):
    def accept_audio(self, pcm: np.ndarray) -> None: ...
    def get_partial(self) -> str: ...
    def pop_final(self) -> str | None: ...
    def reset(self) -> None: ...
```

## 5. 非功能要求
- 纯离线，音频和文字不上传任何服务器（隐私）。
- 4 核 CPU / 8 GB 内存的普通办公本可流畅运行 2 小时以上会议，CPU 占用 < 50%。
- 自动保存：每条定稿立即写入 `~/Library/Application Support/MeetingMinutes/sessions/<时间>.jsonl`；软件崩溃后再次打开提示「发现未完成的会议，是否恢复/导出」。
- 界面语言：简体中文；跟随 macOS 浅色/深色模式。
- Apple 芯片上 onnxruntime 使用 CPU（arm64 原生），性能足够实时；不依赖 GPU。

## 6. 开发里程碑（agent 按顺序执行，每步都要能运行验证）

6. **M6 打包**：PyInstaller 生成 `.app` → 签名（含 entitlements）→ `create-dmg` 生成 `.dmg`；在一台未装 Python 的 Mac 上验证：拖入安装、首次打开、麦克风授权弹窗、录音转写、导出到桌面。

## 9. 建议功能（按需采纳，标注优先级）
- **P1 保存原始录音**：结束时一并保存 mp3 到桌面，方便回听核对。
- **P1 会后精修**：结束后用更大的离线模型对整段录音重新转写 + 重新做说话人分离，准确率明显高于实时结果（耗时约为会议时长的 1/5）。
- **P1 关键词/热词表**：可导入公司人名、项目名、专业术语，提升识别准确率。
- **P2 AI 会议纪要**：在逐字稿之外自动生成「会议摘要、决议事项、待办（负责人+截止日）」，作为 Word 第一页（需要接入大模型，可选离线或云端）。
- **P2 实时编辑**：会议中可直接点击某条文字修改错别字。
- **P2 标记重点**：会议中按快捷键（如 F2）给当前句打星标，导出时高亮。
- **P3 常用参会人名单**：保存姓名和声纹，下次开会自动认人。
- **P3 导出更多格式**：txt / Markdown / PDF。
- **P3 系统声音采集**：线上会议（腾讯会议/飞书/Zoom）时同时录制 Mac 播放的声音，否则只能录到你这一方。macOS 13+ 可用 ScreenCaptureKit 原生实现（需“屏幕录制”权限），或安装免费虚拟声卡 BlackHole。
